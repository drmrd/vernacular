# Ambient-occlusion normals from a dedicated render target Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax. One red-green-blue engine cycle; the rest is derivation, baselines, and documents, following the lane 4 recipe exactly.

**Goal:** Feed GTAO real view-space normals from the depth prepass instead of reconstructing normals from depth (rendering-realism lane 5, issue #471), with the lane 4 gates judging the change, deliberate baseline refreshes on both platforms, and ADR-0173 recording the decision.

**Architecture:** Lane 4's pipeline already renders a depth-only prepass whose color output is unused. The override material gains an output node that writes the view-space normal (`normalView`) into the prepass's default color channel (PassNode textures are half-float by default in r184, so signed components store fine), and the GTAO node consumes `depthPrepass.getTextureNode('output')` as its normal input in place of the null reconstruct-from-depth cast. No multiple-render-target output is needed at all, which keeps the ADR-0151/0172 no-MRT posture intact. The SwiftShader probe on this branch (run 34078575507) recorded `OES_draw_buffers_indexed: true`, `EXT_color_buffer_float: true`, `EXT_color_buffer_half_float: true` (ANGLE over Vulkan SwiftShader), so even the MRT route would have been viable; the probe evidence goes into ADR-0173 and the probe workflow is deleted before merge. If GTAONode expects an encoded normal (raw sampling looks wrong in the liveness check), the fallback is the addon's own example encoding: write `normalView` transformed per GTAONode's sampling convention (read the addon source in node_modules; it samples the texture's rgb directly as a view-space vector).

**Spec:** `docs/specs/2026-09-06-rendering-realism-gates-and-slices.md` (lane 5, issue #471).
