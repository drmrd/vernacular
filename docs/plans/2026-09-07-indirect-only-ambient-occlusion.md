# Indirect-only ambient occlusion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. The engine change runs one red-green-blue cycle; the rest is derivation, baselines, and documents.

**Goal:** Apply ambient occlusion to indirect light only (rendering-realism lane 4, issue #470), refresh every occlusion-affected baseline deliberately on both platforms, re-derive the two ambient-occlusion gate tolerances against the new blend, and record the decision in ADR-0172 superseding ADR-0151's whole-frame multiply.

**Architecture (from the r184 source research, pinned three@0.184.0):** The shipped pipeline multiplies the whole frame by the occlusion term, dimming direct sun. r184 exports `builtinAOContext(aoNode)` from `three/tsl` (src/nodes/core/ContextNode.js:244): installed as a pass context, it routes the occlusion term into three's own `PhysicalLightingModel.ambientOcclusion()`, which multiplies `indirectDiffuse` and applies the roughness-aware curve to `indirectSpecular` while leaving direct light untouched. That is exactly issue #470, with no multiple-render-target output. The install is scene-wide with zero per-material mutation: set `scenePass.contextNode = builtinAOContext(aoNode.context({ getUV: () => screenUV }))` (the `getUV` rebind is mandatory: GTAONode samples at `uv()`, which is mesh UV inside a material; TextureNode honours `builder.context.getUV`, src/nodes/accessors/TextureNode.js:359). The GTAO node feeds from a separate depth-only prepass `pass(scene, camera)` with an `overrideMaterial` so its nested render cannot re-enter the AO context; nested pass scheduling is the ReflectorNode pattern and is re-entrancy safe (NodeFrame stamps frameId before calling). Transparent materials (glass, furniture placeholders) opt out for free (`getAO` returns the input unchanged for `material.transparent`). MRT stays out: r184 fixed the old clear divergence but has a NEW WebGL-fallback divergence (per-attachment blending needs OES_draw_buffers_indexed, which SwiftShader likely lacks), so the no-MRT posture now matters more, and ADR-0172 records that. The pipeline's public shape (`render/setSize/dispose`) is unchanged, so bridge and app code do not move.

**Tech Stack:** three@0.184.0 TSL (`builtinAOContext`, `screenUV`, `pass`, GTAONode addon), the scene-webgl Playwright tier, `refresh-scene-baselines.yml` branch dispatch, the live-view macOS lane (ADR-0171).
